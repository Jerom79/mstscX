# mstscX

**Менеджер RDP-подключений и RemoteApp для Windows.**

**[Скачать последний установщик для Windows x64](https://github.com/Jerom79/mstscX/releases/latest)**

На странице последнего релиза откройте раздел **Assets** и скачайте файл `mstscX-Setup-<версия>.exe`.

mstscX объединяет сохранённые серверы, удалённые рабочие столы и опубликованные приложения в одном интерфейсе. Подключения можно открывать внутри главного окна или в отдельных нативных окнах Windows, настраивать для каждого сервера и запускать повторно из списка.

Автор: **Jeronimo**. Сделано с помощью **Codex**.

## Возможности

### Каталог серверов

- Создание, редактирование, переименование и удаление профилей.
- Отдельные группы удалённых рабочих столов и RemoteApp.
- Три варианта отображения: список, мелкие карточки и крупные карточки.
- Выделение выбранного сервера и отображение состояния подключения.
- Запуск подключений из меню приложения и списка переходов на панели задач Windows.
- Обновление имени открытой сессии при переименовании профиля.
- Закрытие всех подключений одной командой.

### Удалённый рабочий стол

- Подключения внутри главного окна или в отдельном Win32-окне.
- Оконный и полноэкранный режимы, настройки разрешения и глубины цвета.
- Использование нескольких мониторов, если это поддерживается конфигурацией подключения.
- Настройки производительности: обои, анимации, сглаживание шрифтов, воспроизведение видео и отображение окна при перетаскивании.
- Перенаправление буфера обмена, дисков, принтеров, звука и других доступных локальных ресурсов.
- Настройка RD Gateway.
- Сохранение размеров и полноэкранного состояния отдельного окна для каждого профиля.
- Встроенные подключения после перезапуска начинают работу внутри главного окна, а не в сохранённом полноэкранном режиме.
- Предупреждение перед отключением с кнопками «Отключить» и «Отмена». Предупреждение включено по умолчанию и отключается в настройках.

Доступность перенаправления устройств, RemoteApp и отдельных параметров зависит от сервера, групповых политик и возможностей установленного компонента RDP.

### Интерфейс

- Русский и английский языки. При первом запуске русский выбирается для русскоязычной Windows, для остальных языков системы — английский.
- Настройка «Язык приложения»: системный, русский или English. Выбор сохраняется и применяется при следующем запуске, без прерывания текущих соединений.
- Светлая, тёмная и системная темы.
- Полноэкранный режим главного окна: **F11** или кнопка в заголовке.
- Выпадающее верхнее меню в полноэкранном режиме.
- Сворачивание боковой панели и её автоматическое скрытие с анимацией.
- Сохранение положения и размера главного окна. Его полноэкранный режим между запусками не сохраняется.
- При запуске всегда открывается раздел серверов.
- Панель управления полноэкранной RDP-сессией: обычный и компактный вид, закрепление, перемещение вдоль верхнего края.
- Сохранение положения и состояния панели для каждого сервера.
- Необязательное появление компактной панели под курсором: включается в настройках «Вид», по умолчанию отключено.
- Переход из полного экрана в оконный режим перетаскиванием панели.
- Окно «О программе» с иконкой, номером версии и автором.
- Один экземпляр приложения в пользовательском сеансе.

## Требования

### Для запуска

- Windows x64. Минимальная версия, указанная в проекте и установщике: **Windows 10 1809, сборка 17763**.
- Доступный системный компонент клиента удалённого рабочего стола Windows.
- Сетевая доступность сервера: напрямую, через VPN либо через настроенный RD Gateway.
- Учётная запись с правами на нужное RDP-подключение или опубликованное приложение.

Дистрибутив установщика публикуется как **self-contained**: вместе с приложением поставляются используемые компоненты .NET и Windows App SDK. Установка SDK для обычного запуска не требуется.

Хотя в дереве проекта присутствуют стандартные каталоги других платформ MAUI, текущая сборка и функции приложения рассчитаны **на Windows**.

### Для разработки

- Windows x64.
- .NET SDK **10**.
- Рабочая нагрузка .NET MAUI для Windows.
- Windows SDK, совместимый с целевой платформой `net10.0-windows10.0.19041.0`.
- Доступ к NuGet при первом восстановлении зависимостей.
- **Inno Setup 6** — для сборки установщика.

Можно использовать Visual Studio с поддержкой .NET 10 и разработки .NET MAUI либо командную строку с установленными SDK и рабочими нагрузками.

## Установка и обновление

Запустите `mstscX-Setup-<версия>.exe` и выберите установку для текущего пользователя или для всех пользователей. Для установки для всех пользователей потребуются соответствующие права Windows.

Установщик поддерживает русский и английский языки. По умолчанию используется язык интерфейса Windows: русский для русского языка системы, английский для всех остальных. Язык можно изменить в окне выбора языка установки; выбор языка приложения хранится отдельно в его настройках.

Установщик:

- размещает приложение в папке `mstscX`;
- создаёт ярлык в меню «Пуск» и, по выбору, на рабочем столе;
- регистрирует открытие файлов `.rdpx` через mstscX;
- проверяет версию уже установленного приложения;
- предлагает сохранить или удалить пользовательские настройки при удалении приложения.

| Версия установщика относительно установленной | Поведение |
| --- | --- |
| Совпадает | Предлагается переустановка или удаление |
| Новее | Предлагается обновление или удаление |
| Старее | Установка поверх новой версии блокируется; можно отдельно подтвердить удаление текущей версии и установку старой |

Перед обновлением закройте приложение и его подключения. Настройки хранятся отдельно от установленной программы и при обычном обновлении сохраняются. Удаление настроек — отдельное действие при деинсталляции.

Для запуска без установщика можно использовать содержимое `SetupmstscX/Distrib`. Переносить нужно **весь каталог**, включая зависимости, `Images` и файлы ресурсов, а не только EXE. Файловые ассоциации при таком запуске автоматически не регистрируются.

## Начало работы

1. Откройте mstscX и нажмите **«+»** в разделе «Серверы».
2. Укажите название, адрес и имя пользователя. При необходимости сохраните пароль.
3. Выберите встроенное или отдельное окно, параметры экрана и локальных ресурсов.
4. Сохраните профиль и запустите подключение.

Примеры адресов:

```text
server.example.local
192.0.2.10
server.example.local:1111
[2001:db8::10]:3389
```

Если порт не указан, используется стандартный RDP-порт **3389**. При форматировании стандартный порт может не отображаться; нестандартный порт сохраняется.

Параметры можно изменить через кнопку редактирования карточки или контекстное меню. Для каждого сервера доступны собственные настройки экрана, ресурсов, шлюза и RemoteApp.

## RemoteApp

RemoteApp позволяет запускать опубликованное на сервере приложение. В текущей реализации используется нативный Win32-хост; выбор другого механизма внешнего окна в настройках отсутствует.

Профиль RemoteApp содержит:

- программу или опубликованный псевдоним;
- аргументы запуска;
- рабочий каталог;
- параметры получения списка приложений через RD Web Feed;
- сведения об иконке приложения.

В проекте предусмотрено получение списка опубликованных приложений через RD Web и WMI. Доступность этих способов зависит от конфигурации RDS, прав учётной записи и доступности соответствующих служб.

RemoteApp отображается в отдельной группе каталога. Иконки приложений кэшируются локально. Команда подключения Windows PowerShell для профилей RemoteApp не показывается.

## PowerShell

Команда Windows PowerShell находится в меню **«Правка»** и в контекстном меню RDP-сервера.

- Если выбран сервер, открывается системный **Windows PowerShell** с попыткой подключения к нему через WinRM.
- Если сервер не выбран, открывается локальный сеанс Windows PowerShell.
- При наличии сохранённого пароля используется он; иначе запрашиваются учётные данные.
- Нестандартный **RDP-порт не является портом PowerShell**: это разные протоколы.

Для удалённого PowerShell на сервере должен быть настроен WinRM и разрешён доступ для выбранной учётной записи. Успешное RDP-подключение само по себе не означает, что PowerShell Remoting уже настроен.

### TrustedHosts

Если адрес не найден среди явно указанных записей TrustedHosts локального компьютера, приложение предлагает добавить его перед подключением. При согласии:

1. Windows запрашивает повышение прав через UAC.
2. При необходимости запускается локальная служба WinRM.
3. В TrustedHosts добавляется только выбранный адрес, существующие записи сохраняются.
4. Продолжается подключение PowerShell.

Отмена предложения или UAC отменяет запуск подключения. Если настройка управляется групповой политикой, приложение сообщает, что требуется помощь администратора. Приложение не добавляет маску `*`, не включает Basic-аутентификацию и не отключает проверку сертификатов.

Текущий сценарий с явно доверенным адресом использует **HTTP/5985**. В коде также предусмотрен HTTPS/5986 для IP-адреса без явного доверия; это не автоматический поиск доступного порта. Настройка TrustedHosts на клиенте не настраивает серверный WinRM, брандмауэр или VPN.

Сохранённый пароль передаётся процессу PowerShell через именованный канал с ограничением текущим пользователем и проверкой идентификатора процесса. Он не записывается в командную строку запуска.

## Файлы подключений и списков

В меню «Файл» доступны команды:

| Команда | Назначение |
| --- | --- |
| Открыть RDP соединение | Импорт одного подключения из `.rdp` |
| Сохранить RDP соединение | Экспорт выбранного профиля в `.rdp` |
| Открыть список | Загрузка списка серверов из `.rdpx` |
| Сохранить список | Сохранение текущего списка в `.rdpx` |

Открытие файла заменяет текущий каталог профилей, а не добавляет записи к нему. Если уже есть профили или открытые сеансы, приложение запрашивает подтверждение. При подтверждённой замене открытые подключения закрываются.

### `.rdp`

Стандартный текстовый формат параметров подключения удалённого рабочего стола. Экспорт содержит поддерживаемые параметры профиля, включая экран, ресурсы, шлюз и RemoteApp. Сохранённый пароль в экспортируемый `.rdp` не записывается.

### `.rdpx`

Формат списка серверов mstscX на основе JSON. Содержит версию формата, список профилей, их идентификаторы и параметры. При загрузке проверяется структура, корректность адресов и отсутствие повторяющихся имён; размер файла ограничен 32 МиБ.

Текущая версия формата списка — `1`.
В `.rdpx` попадает поле сохранённого **зашифрованного** пароля. Это не переносимый пароль: на другом компьютере или под другой учётной записью Windows его, как правило, потребуется ввести заново. Адреса, имена пользователей и остальные параметры профилей не зашифрованы целиком — учитывайте это при передаче файла.

## Настройки и пароли

Настройки сохраняются через MAUI Preferences в пользовательском каталоге данных приложения внутри %LOCALAPPDATA%. Он отделён от каталога установки: обычное обновление программы не удаляет профили и параметры пользователя.

Пароли защищаются средствами Windows `DataProtectionProvider` с областью `LOCAL=user`. Для резервного копирования списка можно использовать `.rdpx`, но такой файл не обеспечивает перенос сохранённых паролей на другую машину.

Глобальные настройки включают тему, предупреждение перед отключением, автоматическое скрытие боковой панели и поведение компактной полноэкранной панели. Размеры окон и состояние панелей сохраняются отдельно для профилей.

## Сборка из исходников

Все команды выполняются в корне репозитория в PowerShell.

### Подготовка

```powershell
dotnet workload install maui-windows
dotnet restore .\mstscX\mstscX.csproj -r win-x64
```

Также можно открыть решение `mstscX.slnx` в совместимой версии Visual Studio.

### Debug

```powershell
dotnet clean .\mstscX\mstscX.csproj -c Debug -r win-x64
dotnet build .\mstscX\mstscX.csproj -c Debug -r win-x64 --no-restore
```

Результат:

```text
mstscX/bin/Debug/net10.0-windows10.0.19041.0/win-x64/mstscX.exe
```

### Release без установщика

```powershell
dotnet build .\mstscX\mstscX.csproj -c Release -r win-x64
```

### Release и установщик

Установите Inno Setup 6 и выполните:

```powershell
.\SetupmstscX\Build-mstscX.ps1
```

Если компилятор Inno Setup не найден автоматически:

```powershell
.\SetupmstscX\Build-mstscX.ps1 -InnoCompiler 'C:\Program Files (x86)\Inno Setup 6\ISCC.exe'
```

Для запуска двойным щелчком предусмотрен `SetupmstscX/Build-mstscX.cmd`.

После успешной сборки скрипт автоматически публикует установщик в [GitHub Releases](https://github.com/Jerom79/mstscX/releases). Создаётся релиз `v<версия>`, в который загружается **только EXE установщика**. ZIP с приложением и отдельный файл контрольных сумм не загружаются; SHA-256 установщика указан в описании релиза. GitHub самостоятельно предоставляет ссылки на архивы исходного кода.

Для публикации нужна авторизация с правом записи содержимого репозитория `Jerom79/mstscX`: существующая учётная запись Git Credential Manager либо переменная окружения `GH_TOKEN` / `GITHUB_TOKEN`. Токен не следует записывать в файлы проекта. При сетевой ошибке или отсутствии доступа готовый установщик остаётся локально, а скрипт сообщает об ошибке публикации.

Исходники скрипт не коммитит и не отправляет автоматически. Перед сборкой отправьте нужные изменения в основную ветку GitHub: тег нового релиза привязывается к её текущему коммиту. Повторная публикация того же EXE допускается после проверки контрольной суммы; существующий файл с другим содержимым автоматически не заменяется.

Повторить только публикацию, без пересборки и увеличения версии:

```powershell
.\SetupmstscX\Publish-mstscX.ps1 -InstallerPath '.\SetupmstscX\Setup\mstscX-Setup-<версия>.exe'
```

Для локальной сборки без публикации:

```powershell
.\SetupmstscX\Build-mstscX.ps1 -SkipPublish
```

Скрипт сам публикует Release, поэтому предварительно выполнять отдельную Release-сборку не требуется. Он собирает self-contained дистрибутив во временном каталоге, проверяет необходимые файлы, компилирует установщик и затем обновляет результаты:

```text
SetupmstscX/Distrib/                      — готовое приложение и зависимости
SetupmstscX/Setup/mstscX-Setup-<версия>.exe — установщик
```

В дистрибутиве оставляются русские и английские языковые ресурсы; удаляются отладочные и промежуточные файлы и предусмотренные скриптом лишние изображения. Используемые интерфейсные PNG размещаются в `Images`.

После успешного размещения нового установщика старые версионные установщики `mstscX-Setup-*.exe` удаляются из папки `Setup`. Журналы и посторонние файлы не удаляются. До успешного создания нового EXE прежние установщики сохраняются.

Закрывайте приложение перед сборкой, если оно запущено из обновляемого каталога: Windows может блокировать замену EXE и DLL.

### Автоматическое увеличение версии

Перед каждой Release-сборкой увеличивается последнее число версии:

```text
1.0.0.5 → 1.0.0.6 → 1.0.0.7
```

Значение сохраняется в `ApplicationVersion` файла `mstscX.csproj`. Одинаковая версия используется для сборки приложения, файловых метаданных и имени установщика.

- Debug, очистка, восстановление пакетов и сборки для работы дизайнера версию не увеличивают.
- Одна цепочка Build/Publish увеличивает номер один раз.
- Отдельная Release-сборка и последующий запуск скрипта установщика — это две сборки и два увеличения номера.
- Если Release-сборка завершилась ошибкой после выделения номера, номер не откатывается.
- Компиляция только Inno Setup по уже готовому дистрибутиву не увеличивает версию приложения.

Обычная сборка создаёт в корне репозитория ярлык с конфигурацией и временем создания. Предыдущий ярлык соответствующей конфигурации удаляется перед сборкой. Скрипт упаковки использует отдельный временный путь ярлыка.

& 'C:\Program Files (x86)\Inno Setup 6\ISCC.exe' /O- /Q .\SetupmstscX\mstscX.iss

Эти проверки не заменяют ручное тестирование RDP, RemoteApp, нескольких мониторов, обновления установленной версии и подключения PowerShell в целевой сети.

## Диагностика

В текущем коде оставлена временная диагностика переходов полноэкранных RDP-сессий. Журнал `fullscreen-transition.log` записывается:

- в Debug — рядом с исполняемым файлом;
- в Release — в подкаталог `Logs` каталога данных приложения.

При достижении порога размера журнал переносится в `fullscreen-transition.log.previous`. Перед публикацией журналов просматривайте их содержимое и удаляйте сведения, которые не хотите раскрывать.

При сообщении об ошибке полезно указать:

1. Версию mstscX из окна «О программе» и версию Windows.
2. Тип подключения: RDP или RemoteApp, встроенное или отдельное окно.
3. Количество мониторов и масштаб интерфейса на них.
4. Запущено ли само приложение локально или внутри другого RDP-сеанса.
5. Последовательность действий, ожидаемый результат и фактическое поведение.
6. Текст ошибки и подходящий фрагмент журнала без паролей и лишних персональных данных.

### Частые вопросы

**Рабочий стол подключается, а PowerShell — нет.** Проверьте серверный WinRM, права пользователя и сетевую доступность его порта. RDP и WinRM работают независимо.

**После переноса списка на другой компьютер не подходит сохранённый пароль.** Защищённые пароли привязаны к пользовательскому контексту Windows. Введите пароль заново на целевой машине.

**После копирования EXE нет иконок или приложение не запускается.** Копируйте весь `Distrib`, включая зависимости и ресурсы, либо используйте установщик.

## Разработка

Правила интерфейса находятся в [AGENTS.md](AGENTS.md). Заголовки верхнего меню выводятся текстом, а действия внутри выпадающих и контекстных меню сопровождаются подходящими иконками. Одинаковые действия должны использовать одинаковые значки.

Не включайте реальные профили серверов, пароли, пользовательские экспорты и диагностические журналы в публичные изменения. При изменении хранения данных учитывайте совместимость уже установленных версий и формата `.rdpx`.

Условия распространения и использования исходного кода определяются лицензией репозитория. Этот README сам по себе не назначает проекту лицензию.
